# Native share-sheet setup (F1-F3)

The Dart-side wiring at `lib/features/sharing/` is complete. The OS-side
configuration that actually delivers shares to Quill needs platform-
specific work in Xcode and the Android manifest.

## Android — DONE (F3, M1360)

`android/app/src/main/AndroidManifest.xml` has the three intent-filters
that `receive_sharing_intent` v1.8.x expects:

```xml
<intent-filter>
    <action android:name="android.intent.action.SEND"/>
    <category android:name="android.intent.category.DEFAULT"/>
    <data android:mimeType="text/plain"/>
</intent-filter>
<intent-filter>
    <action android:name="android.intent.action.SEND"/>
    <category android:name="android.intent.category.DEFAULT"/>
    <data android:mimeType="text/*"/>
</intent-filter>
<intent-filter>
    <action android:name="android.intent.action.SEND_MULTIPLE"/>
    <category android:name="android.intent.category.DEFAULT"/>
    <data android:mimeType="text/*"/>
</intent-filter>
```

`MainActivity` is already `singleTop` and `exported`, so no further
Android-side changes are required to bring up "Share → Quill" in
Chrome / Firefox / etc.

Smoke test on a device or emulator:
```
adb shell am start -a android.intent.action.SEND -t text/plain \
    --es android.intent.extra.TEXT 'hello quill' \
    -n com.example.my_notion/.MainActivity
```
Expected: Quill opens; the share lands in `Inbox/Quick capture.md`.

## iOS — TODO (F4+)

Requires a new **Share Extension** target in
`ios/Runner.xcodeproj`. This can't be done by editing text files alone
— `project.pbxproj` is fragile + targets need Xcode's "Add Target →
iOS → Share Extension" wizard. Follow the canonical setup from the
`receive_sharing_intent` package's example app:

1. **In Xcode:** File → New → Target → iOS → Share Extension. Name it
   `Share Extension`, bundle ID `com.example.myNotion.ShareExtension`
   (or whatever matches `ios/Runner/Info.plist`'s base bundle ID with
   `.ShareExtension` appended).

2. **Add an App Group** to BOTH the Runner target and the Share
   Extension target. Identifier convention: `group.<base bundle ID>`.
   Both targets need to:
   - Signing & Capabilities → "+ Capability" → App Groups
   - Tick the new group on both sides.

3. **Replace `ShareViewController.swift`** (generated by Xcode) with
   the version from
   `~/.pub-cache/hosted/pub.dev/receive_sharing_intent-1.8.1/example/ios/Share Extension/ShareViewController.swift`.
   Update the `appGroupId` and `hostAppBundleIdentifier` constants at
   the top.

4. **Edit the Share Extension's `Info.plist`** so `NSExtensionAttributes`
   accepts the right types. From the package's example:
   ```xml
   <key>NSExtensionAttributes</key>
   <dict>
       <key>NSExtensionActivationRule</key>
       <dict>
           <key>NSExtensionActivationSupportsText</key>
           <true/>
           <key>NSExtensionActivationSupportsWebURLWithMaxCount</key>
           <integer>1</integer>
       </dict>
   </dict>
   ```

5. **Edit `Runner/Info.plist`** to add the custom URL scheme the
   extension opens the main app with:
   ```xml
   <key>CFBundleURLTypes</key>
   <array>
       <dict>
           <key>CFBundleURLSchemes</key>
           <array>
               <string>ShareMedia-com.example.myNotion</string>
           </array>
       </dict>
   </array>
   ```

6. **Add `LSApplicationQueriesSchemes`** so the extension can open the
   main app on iOS 9+:
   ```xml
   <key>LSApplicationQueriesSchemes</key>
   <array>
       <string>ShareMedia-com.example.myNotion</string>
   </array>
   ```

7. Build + sign both targets with matching team / provisioning. The
   first launch may need a fresh `flutter clean && flutter run` to
   regenerate the Generated.xcconfig the Share Extension target now
   reads from.

### Smoke test on iOS

1. Build and install: `flutter build ios --debug && open ios/Runner.xcworkspace`,
   then archive + run on a device (or simulator).
2. Open Safari, navigate to any page, tap Share → Quill (should appear
   after a fresh install).
3. Confirm: app opens; the URL lands as a new line in
   `Inbox/Quick capture.md`.

## Home-screen widgets — partial (G1, M1368)

Dart side wired via `home_widget: ^0.7.0` and a new
`lib/features/sharing/data/home_widget_source.dart`. It implements
the same `IncomingShareSource` interface as the share-sheet plugin,
so widget-originated captures drain through the existing
`IncomingShareBinder` → `QuickCapture.append` flow.

The OS-side widget targets still need manual setup; canonical
example lives at the `home_widget` package's `example/` directory.

### iOS WidgetKit (TODO)

1. In Xcode: File → New → Target → iOS → Widget Extension. Match
   the bundle ID convention you used for the Share Extension
   (`com.example.myNotion.QuickCaptureWidget`).
2. Tick the same App Group both targets.
3. Write a small `TimelineProvider` that surfaces an "Add to Inbox"
   button. The button's tap intent writes the user's input to the
   shared `pending_capture` key via the `home_widget`
   App-Group-backed UserDefaults shim, then opens the host app via
   the `ShareMedia-…` URL scheme already declared for the Share
   Extension.
4. Dart-side: nothing else to do — `HomeWidgetSource` polls
   `pending_capture` on every `HomeWidget.widgetClicked` event.

### Android AppWidget (TODO)

## macOS — N/A (F5+)

`receive_sharing_intent` is iOS/Android only. macOS share-sheet
integration would need a separate Share Extension target in
`macos/Runner.xcodeproj` using AppKit's `NSSharingService` framework,
and the Dart side would need a fresh channel — neither is currently
in scope. Backlog item.
